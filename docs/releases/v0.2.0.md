# v0.2.0 — Media signaling and native backend integration

This release expands the Skype for Business TypeScript SDK with typed call
signaling, conditional application-sharing operations, and account-scoped
integration for a compatible host media engine. **A native media engine is not
bundled. Actual screen transmission on macOS or Windows is not yet qualified.**

## Added

- `session.media`: start/add/stop audio and video, SDP offer/answer helpers,
  invitation control, participant mute operations, negotiation and sharing
  resources, media policies, and temporary relay credentials.
- Conditional `startApplicationSharing`, `addApplicationSharing`, and
  `stopApplicationSharing` extensions. Each follows an exact server-advertised
  relation. Native metadata establishes their field names; the add operation's
  POST mapping remains inferred and unqualified on a live deployment.
- `mediaEngine` on `SkypeForHoo` and `UcwaSessionOptions`, with lazy initialization
  once per session and explicit capabilities by feature, direction and capture
  source.
- `session.screenSharing`: manage desktop/window publishing and incoming viewing
  through the configured engine, cancellation, natural termination and retryable
  cleanup. Without an engine, support is unavailable and starts throw
  `UnsupportedMediaError`.
- Optional engine `handleEvents` runs automatically before `session.events()`
  yields each batch. Handler failures preserve the cursor for replay.
- `mediaCleanupTimeoutMs` and `MediaCleanupTimeoutError` bound account cleanup
  and stopping all shares. Late results retain cleanup handlers; a deadline does
  not establish that native resources have been released.
- `session.reportActivity()` follows `me.reportMyActivity` for actual host activity.
- An [API/runtime map](../architecture.md), [media guide](../media.md), and
  updated [desktop integration brief](../desktop-app.md) for macOS and Windows.

Session shutdown sends the UCWA application's DELETE independently of native
cleanup. The host owns credentials, permissions, persistence, event supervision,
and the compatible media implementation.

## Verification

The local `npm run check` passes 94 synthetic tests, the build, and independent
Node/browser declaration checks. The fixtures cover protocol serialization,
event replay, backend lifecycle, cancellation, late startup results, deadlines,
and shutdown. They do not connect an enterprise account or send real media.

The complete capability and interoperability boundary is in the
[media guide](../media.md). macOS and Windows are the first native backend targets;
capture, codecs, protected transport and real-peer acceptance remain required
before claiming working calls or screen sharing.

## Install

The release contains a built ESM package with TypeScript declarations and no
runtime dependencies. Node.js 22 or later is supported.

```sh
npm install https://github.com/openhoo/skypeforhoo/releases/download/v0.2.0/skypeforhoo-0.2.0.tgz
```

This publishes the package through GitHub Releases. It is not an npm registry
publication.
