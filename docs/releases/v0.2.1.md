# v0.2.1 — Authentication and lifecycle fixes

This patch fixes five defects found during expanded smoke testing of the Skype
for Business TypeScript SDK. It retains the public API and native media backend
requirements from v0.2.0.

## Fixed

- Password authentication now recognizes `MsRtcOAuth` only at a real scheme
  boundary. Quoted Bearer/Digest values and substring schemes cannot trigger a
  password request. Parameters stay scoped to that scheme; malformed or duplicate
  parameters are rejected. Spaces and tabs around `=` remain supported.
- Cancelled or superseded token acquisitions cannot overwrite a newer cached
  token. Shared acquisitions and independent caller cancellation are preserved.
- A delayed messaging-capability lookup cannot start a message POST after the
  session closes or the caller cancels.
- Availability changes invalidate hub lookups already in flight. Original waiting
  callers and later operations receive current capabilities instead of stale
  operation links.
- Redirect and authentication-response body cleanup respect request timeout and
  cancellation, including custom Fetch adapters with delayed cancellation.
  Cleanup errors preserve an existing authentication failure and cannot cause
  replay after cancellation.

## Verification

- All 222 tests pass on Node 24.22.1 and Node 26.13.0, including all six original
  failing smoke reproducers. No tests are skipped or cancelled.
- The full Node 24 check passes source typechecking, tests, build, and independent
  Node/browser consumer declaration checks.
- The packed SDK completes 8,048 real loopback HTTPS requests across 16 concurrent
  synthetic accounts and 192 connect/close cycles: 960 follow-up message
  submissions, 1,152 correlated events, and recovery from 16 injected DELETE 503
  failures. No registrations, sessions, polls, control requests or sockets remain.
- Chrome 156.0.8078.80 completes 939 HTTPS requests, including 432 native CORS
  preflights, across 12 synthetic account flows and 288 event batches. The
  misleading Bearer challenge is rejected with zero unintended password requests.
- The Node package test keeps TLS verification enabled and proves rejection of an
  untrusted fixture certificate. The browser uses a fresh context that ignores
  only its synthetic fixture certificate errors.

Repeatable package/browser harnesses and the expanded regression suite are
included in the source repository. The published package contains built ESM,
TypeScript declarations and documentation, with no runtime dependencies.

## Qualification

The HTTPS and browser CORS checks use real transports with synthetic services,
accounts, credentials, recipients and media backends. Authenticated enterprise
sign-in, real recipient delivery, federation and native audio/video/screen
transmission remain unqualified. A compatible host media engine is still required.

## Install

Node.js 22 or later is supported. Install the built GitHub release asset:

```sh
npm install https://github.com/openhoo/skypeforhoo/releases/download/v0.2.1/skypeforhoo-0.2.1.tgz
```

Distribution is through GitHub Releases. This is not an npm registry publication.
